# v0.4.2b

发布日期：2026-10-02

变更时间：2026-10-02

本次更新完善角色卡技能系统与职业系统：按 COC 7e 官方基础值校准技能目录，新增技能专精选择与多层可配置的技能基础值体系；并将内置职业扩充至 11 类共 112 个，支持分类选择与一键就职。

## 新增

- 技能目录按官方基础值校准：读唇 1、计算机使用 5、爆破 1、炮术 1、电子学 1；并按用户补充写入催眠 1、潜水 1、驯兽 5、狙击枪 5。
- 格斗专精基础值：斗殴 25、剑 20、矛 20、斧 15、绞索 15、链锯 10、连枷 10、鞭 5；射击专精基础值：手枪 20、步/霰 25、冲锋枪 15、狙击枪 5、弓 15、机枪 10、重武器 10。
- 技能专精改为「按钮 + 弹窗」：带专精的技能在技能名右侧显示按钮，未选择时显示「选择{技能名}」（如「选择语言」），点击后弹窗单选出该技能的专精，确认后按钮显示专精名且基础值切换为该专精的基础值；取消与确认均可回退。
- 专精写入通过 `applySkillSpecialty(技能行, 专精键)` 统一完成，选择职业等流程可直接调用以写入专精并重算基础值。
- 技能基础值支持三层配置：管理员设置（角色卡规则）、房间规则、用户个性化设置（保存在当前浏览器），三处均可点击「设置技能基础值」弹窗按技能（含专精）逐个覆盖，留空表示沿用默认值。
- 生效优先级为：房间规则 > 用户个性化 > 管理员设置（仅兜底）> 技能目录默认 > 动态值（闪避 = DEX/2、母语 = EDU）；管理员默认值仅在房规与用户个性化都未填写时生效。
- 自定义技能（`custom`）不设默认基础值，由用户在技能行直接填写。
- 进入房间选择角色卡或绑定角色卡时，若角色卡基础值超过房间规则上限则提示；用户确认继续后自动把超出部分降低为房间规则上限并重算成功率，取消则回到选择界面另选角色卡。
- 导入角色卡时以导入文件中的技能基础值为主，并提示其中超过设定上限的技能名。

## 聊天与房间体验

- 聊天消息中的图片显示为缩略图（最大 260×200），点击后在当前页面内的浮层放大预览（Esc 或点击遮罩关闭），不跳转、不下载。
- 聊天消息中的视频改为内嵌播放器直接播放，并提供「放大」按钮在页面内全屏浮层播放。
- 房间成员离线/上线时通过 Socket.IO 广播 `room_members_changed`，房间内其他玩家即时刷新在线状态。
- 用户角色被调整（如管理员降级为 user）时广播 `role_changed` 与 `room_members_changed`：房间成员列表按实时角色渲染配色与标签，降级后不再保留管理员配色，当事人权限即时刷新。
- 聊天输入框上方显示「xxx 正在输入」提示（多人时合并显示，4 秒无输入自动消失）。
- 修复自己发送的长消息换行后未左对齐的问题。

## 职业系统

- 内置职业由 1 个扩充至 112 个，按 11 个类别组织（文艺工作、工农商、职工、学者、医疗系统、运动/探险、服务业、宗教相关、灰色/无职、罪犯、军警政）；每个职业一个 JSON（`data/occupations/builtin/<id>.json`），含 `nameKey`/`categoryKey`（i18n 键，中英双语）、`creditRating`、`occupationSkillPoints.terms`、`occupationSkills`、`skillBases`。
- 「选择职业」弹窗改为类别手风琴：初始只列类别行（含职业数量），点击展开为该类别 2 列网格的职业卡片；卡片显示职业名、本职技能、信用评级、职业点数。
- 卡片「就职」一键完成：写入职业名、按 `terms` 自动算出职业点数写入「职业点数」栏位（`choose` 项取候选属性最高值，如音乐家 = EDU×2 + DEX/POW×2 较高者）、自动勾选确定的专职技能，并对带专精的本职技能写入专精并重算基础值（「或」「任意 N 项」等模糊条目不打勾、不写专精）。
- 技能列表上方新增一行提示：职业名、信用评级、全部本职技能（含「或」「任意 N 项」等模糊表述）。
- 职业本职技能条目区分三类语义：确定技能（打勾）、`chooseOne`（「A 或 B」）、`freeChoice`（「任意 N 项…」）；打勾判定仅取确定技能。
- 新增 `tests/test_occupation_catalog.py`（6 条校验）：文件与 id 一致且唯一、必填字段与 `categoryKey` 合法性、信用评级范围、点数 `terms` 合法（`attribute`/`choose` 均为合法属性键、`multiplier` 为正整数）、本职技能的 `skillKey`/`specialtyKey` 存在于技能目录、`skillBases` 键存在于技能目录。

## 修复

- 修正多处以 0 作为默认基础的技能（读唇 / 计算机使用 / 爆破 / 炮术 / 潜水 / 电子学），此前与官方值不符。
- 修正闪避、母语的动态基础值此前被静态默认值短路、始终不生效的问题。
- 修复技能专精弹窗与既有同名弹窗 id 重复导致的渲染异常。
- 修复 TOML 字符串值读取时未还原 `\"`、`\\` 等转义导致嵌套配置（以 JSON 字符串保存的技能基础值）读不到、且反复保存会不断叠加转义的问题。
- 自动存档改由服务端系统后台定时触发：不再依赖玩家浏览器的定时器，服务端按 `general.toml` 的 `[autosave]`（`enabled`/`interval`）为到期的活跃房间写入自动存档节点，触发来源记为系统；写入后广播 `room_autosave_created` 让房间内客户端刷新节点列表。
- AI KP 不再编造 COC7 目录中不存在的技能：检定名会对照技能目录（含专精，兼容常见中文变体）校验，未知技能直接拒绝并提示改用标准检定名；系统提示同步强调只能使用标准属性或角色卡上已有的技能。
- 修复「导入剧本」时 AI 不遵循剧本的问题（不再依赖压缩上下文，改为补齐剧情来源与结构索引）：
  - 新增 `KnowledgeBaseService.catalog()`，按知识块顺序生成章节目录；直接导入的剧本会把该目录注入系统提示，让模型像普通剧本一样先掌握整体剧情结构。
  - 直接导入剧本的检索结果保留全文（不再按 1200 字符截断），并单独放大直接导入的召回章节数，减少情节被截断或漏检。
  - 场景静态核心纳入 `global_summary`，导入剧本的剧情简介随每次请求稳定注入。
  - 直接导入剧本时不再向模型暴露 `room.get_scenario_module` / `room.activate_scenario_scene` 这两个无意义的场景工具，避免模型反复无效调用并浪费轮次。
- 降低 AI token 改用不损失信息的方式：撤销此前的上下文压缩（场景静态卡有界、历史 6000/10、工具结果 2000 字符、折叠旧工具结果均已回滚），改为通过「导入剧本目录 + 全文检索」保证剧情完整性，并通过裁剪无意义工具、稳定系统提示前缀（命中 provider 前缀缓存）来控制开销。
- 修复导入剧本「知识库召回始终固定、不随剧情推进变化」的问题：
  - 检索 query 由「仅当前一句」改为拼接最近 3 轮对话（每条截断 500 字符、总量 1500 字符），泛化输入也能带上剧情上下文参与匹配。
  - 词法分改用 BM25（IDF 在硬过滤后的子语料上计算），冷门词（专有人名/地名）权重更高；词法与向量分各自归一化到 [0,1] 后按查询类型动态调权（规则类问题偏词法，叙事类偏向量）。
  - 新增房间级章节游标 `rooms/<room_id>/knowledge_cursor.json`（`{scenario, rounds}`）：最近 `sticky_rounds` 轮召回过的章节排序加权、最近 `cooldown_rounds` 轮召回过的章节排序降权；只调整排序，不截断或压缩内容，兜底路径同样优先返回冷却之外的章节。
- 优化导入剧本的「遗忘」兜底：词法与向量均未命中时仍返回知识块（导入剧本没有场景模块，内容仅在知识块中），避免模型因检索为空而声称剧本缺失。
- 优化导入剧本的切块与召回（父子块）：
  - 按 Markdown 标题与「第X章/节/幕/场景」标题分块（一个场景/章节一块）；仅当正文超过子块上限时才继续切分，且优先在自然段边界处切分，避免句子被拦腰截断。
  - 每个子块写入所属章节（`chapter_path` / `metadata.section`）；检索命中子块后按 chunk 顺序向两侧回填同章节的相邻块（受父块上限约束），合并为一条「完整章节」结果，续块重复的「【章节】」前缀会被去重。
  - 因此返回条数天然收敛为「章节数」，在不截断内容的前提下减少重复上下文。
- 知识库检索与剧本切块改为可配置：管理员设置页新增「知识库检索与剧本切块」区块，对应 `general.toml` 的 `[ai.knowledge]`：
  - `top_k_default`（默认 5，1-32）：带场景模块的剧本每次召回的章节数量。
  - `top_k_direct`（默认 6，1-32）：直接导入剧本每次召回的章节数量。
  - `chunk_child_max_chars`（默认 800，200-8000）：导入剧本子块字符上限，越小召回越精确，修改后需重新导入剧本才会生效。
  - `chunk_parent_max_chars`（默认 2400，200-16000）：命中后回填同章节内容的字符上限。
  - `sticky_rounds`（默认 1，0-10）/ `cooldown_rounds`（默认 3，0-20）：章节粘滞与冷却轮数。
- 历史压缩改为「双层滚动摘要 + 关键事实」：压缩时把已有滚动摘要与新增对话一并交给模型融合，输出 `{narrative ≤250字, key_facts[...]}`；关键事实按 地点/NPC/物品/决策 分类落盘，避免叙事压缩后关键剧情事实丢失。模型返回非 JSON 时自动退化为纯文本摘要。
