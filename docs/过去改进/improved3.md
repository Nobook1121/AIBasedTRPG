## 1. 核心目标

- 大幅降低 AI KP 的 token 消耗。
- 提升 LLM 前缀缓存 / 显式上下文缓存命中率。
- 严格防止不同剧本、不同版本、不同房间之间剧情串扰。
- 支持剧本频繁修改，不影响进行中的房间。
- 防止 AI 剧透、偏离剧本、引用未解锁内容。

## 2. 关键设计（按优先级）

### 2.1 知识库（新建，最高优先级）

**入库**：把剧本拆成结构化卡片，而不是按字数硬切。卡片类型按照已有的剧本模块分类（为后续可能添加的新卡片类型留空间）：



每个 chunk 必须带元数据：
`scenario_id`, `scenario_version`, `scene_id`, `card_type`, `visibility (kp_only/player_visible)`, `spoiler_level`, `unlock_condition`, `text`, `embedding`。

若现有分块系统不产出上述字段，请扩展它，而不是另起炉灶。

**检索**：提供统一服务 `search(roomId, query)`，业务层不得直接访问向量库。流程：

1. 读取房间的 `scenario_id + scenario_version + current_scene + 当前剧透等级`
2. **先硬过滤，后向量相似度**：
   ```
   scenario_id = 当前剧本
   AND scenario_version = 当前房间版本
   AND (scene_id = 当前场景 OR scene_id IS NULL)
   AND spoiler_level <= 当前进度
   ```
3. 向量检索 topK
4. （可选）BM25 / 关键词检索补充专有名词
5. （可选）RRF 融合 + reranker 重排
6. 返回 top 3~5 压缩卡片

**隔离**：优先每剧本独立 namespace/partition；若共享 collection，`scenario_id + scenario_version` 过滤为强制，封装服务防漏加。

### 2.2 缓存分层（改进）

- **Provider 前缀缓存**：固定内容放最前，动态放后面，前缀字节级稳定
- **显式上下文缓存**：剧本 core 层按 `scenario_id + version` 建缓存，后续引用
- **应用层精确缓存**：键含 `scenario_id + version + scene_id + 状态摘要哈希`
- **房间缓存**：键必须含 `room_id`
- **版本失效**：用版本号，不用时间戳；新版本独立键，旧版本保留至无活跃房间

### 2.3 Prompt 分层组装（改进与新建）

从前到后：

1. 全局系统层（完全固定，所有剧本共享）
2. 剧本静态 core 层（按 `scenario_id + version` 固定）
3. 当前场景层（按 `scene_id + version` 固定）
4. 知识库检索结果（动态）
5. 房间状态投影（动态）
6. 最近 N 轮对话（动态）
7. 当前玩家输入

**关键**：1-3 中不得插入 room_id、玩家名、时间戳、随机数、动态状态，否则破坏前缀缓存。

### 2.4 剧本版本化（新建，与知识库强耦合）

- 剧本有 `scenario_id`（永久）+ `scenario_version`（每次发布递增）
- 草稿编辑 → 测试沙盒 → 发布新版本 → 异步重建该版本知识库索引 → 预热缓存
- 新房间默认绑最新版本；旧房间锁创建时版本，不自动升级
- 提供显式“迁移到新版本”，需满足：进度可映射、实体可对应、场景边界、可回滚
- 所有缓存键、知识库过滤、房间状态都必须带版本
- 下架 / 回滚 / 归档策略：有活跃房间的版本禁止删除，只能归档
- 在剧本卡牌显示剧本id和剧本版本，编辑和预览也显示
- 优化剧本创建，将保存和发布分离。

### 2.5 结构化输出与状态校验（新建）

大模型只输出 JSON，后端执行状态更新：

```json
{
  "narration": "...",
  "options": ["...", "..."],
  "state_updates": { "triggeredEvents": [], "unlockedClues": [], "npcAttitudes": {}, "inventory": [], "san": 0 },
  "next_scene": "...",
  "npc_actions": []
}
```

校验：`next_scene`、`npc_id`、`clue_id`、`item_id` 必须在当前剧本版本白名单内；非法则拒绝或降级，不轻易重试大模型。

### 2.6 房间状态外置（检查现有实现）

- 状态存 Redis / DB，每轮只注入当前场景需要的投影
- 旧对话压缩为结构化事件日志（如“玩家救下 NPC，获得钥匙，态度 +1”）
- 最近 N 轮原文单独保留，其余走摘要

如果现有房间管理已经做到，只需检查并补充“状态投影”和“滚动摘要”部分。

## 4. 测试与验收

- **防串**：构造两个相似剧本（都有灯塔、失踪、邪教），交叉提问，断言 top-k 不含其他 `scenario_id`。
- **缓存命中**：同剧本同场景多轮，前缀缓存命中率 > 80%。
- **版本迁移**：旧房间迁到新版本，状态正确映射。
- **防剧透**：未解锁线索不被检索，AI 不主动提及。
- **token 对比**：全量注入 vs 按需检索，输入 token 下降 > 60%。
- **结构化输出**：非法实体、非法状态更新被拒绝。

监控指标：缓存命中 token 占比、每轮输入/输出 token、每房间成本、场景切换后缓存命中率、AI 偏离率、检索结果 `scenario_id` 分布异常告警。
